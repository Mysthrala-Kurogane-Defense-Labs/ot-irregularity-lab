# Dataset generation

Each run writes `telemetry.parquet`, `ground_truth.json`, `run_metadata.json`, and the resolved `scenario.yaml`. Ground truth schema v1.1.0 includes event intervals and actual operating-regime intervals even if regime tags are hidden from telemetry. CSV and JSONL telemetry exports are opt-in. Batch suites write independent seeded runs under `train/`, `validation/`, and `test/`, plus model-ready concatenated `train.parquet`, `validation.parquet`, and `test.parquet` files at the dataset root. The `dataset_manifest.json` records suite/simulator/schema versions, counts, disjoint seeds, observations, per-run and partition artifact hashes, and realized class, event, asset, and regime distributions. Every concrete sampled parameter is recorded in its run scenario so `replay` can reproduce that run exactly. The suite YAML is copied into the dataset root. The manifest describes the generated dataset; it is not a signed provenance attestation.

Batch creation requires a new output path and stages the complete dataset in a temporary sibling directory before publishing it atomically. Use `--resume` to keep validated per-run checkpoints and continue after interruption; rerun with the same suite, run count, seed, simulator version, and schema version.

Partitions use distinct seeds and run IDs. A release manifest records resolved scenario hashes, observation counts, class, event, asset, and regime distributions, generator arguments, software lockfile hash, and data license. Public datasets contain synthetic, generated, non-customer data only.

The randomized `training-v0.2` suite mixes normal and fault-bearing runs with weighted asset/operating profiles and explicit type-specific parameter distributions. It declares CC BY 4.0 for generated outputs. Create it with `uv run ot-lab dataset create --suite suites/training-v0.2.yaml --runs 3000 --seed 20261003 --output datasets/ot-irregularity-training-v0.2 --resume`. The default 35%/65% normal/event-bearing mix is a benchmark design choice, not a claim about plant failure prevalence. Challenge generation draws a hidden runtime seed and concrete ranged parameters in an evaluator-controlled process, does not persist the resolved scenario/seed, and discards the temporary case after scoring.

For event-free training data, use `suites/normal-operation-v0.1.yaml`. For normal-but-demanding false-positive stress, use `suites/false-positive-stress-v0.1.yaml`, which adds cold/warm starts, rapid recipe/load changes, high-load operation, maintenance, shutdown/restart, broad ambient ranges, and temporary sampling jitter. Both vary per-asset load setpoint, sensor noise and thermal response; every sampled process parameter is resolved into `scenario.yaml` and included in its scenario hash for replay and provenance. These ranges provide synthetic diversity and are not industrial population estimates. For the separate runtime challenge distribution, use `ot-lab challenge --suite suites/training-v0.2.yaml --challenge-suite suites/challenge-v0.1.yaml --image IMAGE --output RESULTS`; challenge outputs do not persist ground truth or hidden run details.

The public 1,000-run release is available from the [OT Irregularity Dataset v0.2.0 release](https://github.com/Mysthrala-Kurogane-Defense-Labs/ot-irregularity-lab/releases/tag/dataset-v0.2.0).

Create separate publishable partition artifacts from a completed dataset with `uv run ot-lab dataset package --dataset datasets/ot-irregularity-training-v0.3 --dataset-version 0.3.0 --data-license CC-BY-4.0 --license-file DATASET_LICENSE.txt --output releases/ot-irregularity-training-v0.3.0`. The explicit license identifier must match the suite when one is declared; suites without one require a deliberate publisher choice. The command validates source hashes and creates `train.zip`, `validation.zip`, and `test.zip`; select a subset with `--partition train test`. Each ZIP contains only its Parquet partition, the supplied license notice, and a seed-free `release_manifest.json`. The output directory includes another release manifest with artifact hashes, sizes, counts, and class/event/asset distributions. Outputs are deterministic for the same dataset, version, license bytes and selected partition order. The release manifest links to the original `dataset_manifest.json` by SHA-256 without copying its per-run seeds. Challenge cases are ephemeral and cannot appear as batch partitions.

OT Irregularity Dataset v0.3.0 is generated from the same versioned v0.2 suite with simulator v0.3.0 and an independent master seed. It is a new artifact; it does not replace v0.2. See the [public release](https://github.com/Mysthrala-Kurogane-Defense-Labs/ot-irregularity-lab/releases/tag/dataset-v0.3.0), its [generation record](docs/workflows/synthetic-dataset-generation/runs/2026-10-03-training-v0.3-1000.md), and archive hash there.
