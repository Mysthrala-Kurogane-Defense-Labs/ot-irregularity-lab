# Dataset generation

Public dataset analysis informs scenario families but does not set field prevalence or detector behavior. See the [dataset pattern review](DATASET_PATTERN_REVIEW.md) for sources, licensing boundaries and the new randomized compressor air-leak scenario.

The current public synthetic release is [OT Irregularity Dataset v0.5.0](https://github.com/Mysthrala-Kurogane-Defense-Labs/ot-irregularity-lab/releases/tag/dataset-v0.5.0), containing 3,000 train/validation/test runs. It publishes telemetry and labels as separate archives; `SHA256SUMS.txt` verifies the archives, license, and release manifest. All assets were downloaded from GitHub and checked against their published hashes. See the [generation and public-download verification record](docs/workflows/synthetic-dataset-generation/runs/2026-10-04-training-v0.5-3000.md). The [v0.4.0 release](https://github.com/Mysthrala-Kurogane-Defense-Labs/ot-irregularity-lab/releases/tag/dataset-v0.4.0) remains available as a historical dataset.

A 3,000-run v0.5.0 dataset was generated from `training-v0.3` with simulator 0.4.0. It contains 31,114,700 observations and 393 air-leak events (222/87/84 across train/validation/test); generation, replay, package, and public download checks are recorded in [the v0.5 generation record](docs/workflows/synthetic-dataset-generation/runs/2026-10-04-training-v0.5-3000.md). Its public package separates telemetry from labels and is licensed CC BY 4.0.

Each run writes `telemetry.parquet`, `ground_truth.json`, `run_metadata.json`, and the resolved `scenario.yaml`. Ground truth schema v1.1.0 includes event intervals and actual operating-regime intervals even if regime tags are hidden from telemetry. CSV and JSONL telemetry exports are opt-in. Batch suites write independent seeded runs under `train/`, `validation/`, and `test/`, plus model-ready concatenated `train.parquet`, `validation.parquet`, and `test.parquet` files at the dataset root. The `dataset_manifest.json` records suite/simulator/schema versions, counts, disjoint seeds, observations, per-run and partition artifact hashes, and realized class, event, asset, and regime distributions. Every concrete sampled parameter is recorded in its run scenario so `replay` can reproduce that run exactly. The suite YAML is copied into the dataset root. The manifest describes the generated dataset; it is not a signed provenance attestation.

Batch creation requires a new output path and stages the complete dataset in a temporary sibling directory before publishing it atomically. Use `--resume` to keep validated per-run checkpoints and continue after interruption; rerun with the same suite, run count, seed, simulator version, and schema version.

Partitions use distinct seeds and run IDs. A release manifest records resolved scenario hashes, observation counts, class, event, asset, and regime distributions, generator arguments, software lockfile hash, and data license. Public datasets contain synthetic, generated, non-customer data only.

The randomized `training-v0.2` suite is retained with its original 15 fault families. `training-v0.3` adds a compressor `air_leak` family with seeded onset, duration, severity, progression and numeric pressure/current effects while retaining normal runs and the existing asset/regime mix. Additional compressor-containing cells and an explicit event weight raise exposure to the new family while preserving standalone and mixed asset profiles. The suite guarantees at least one air-leak run per partition, capped at 10% of the partition size for small datasets and 50 for larger ones. These earliest partition-local indices are forced event runs; subsequent runs follow the declared random mixture, and seeds remain independent. Generate a candidate with `uv run ot-lab dataset create --suite suites/training-v0.3.yaml --runs 1000 --seed 20261005 --output datasets/ot-irregularity-training-v0.5-candidate`. The declared normal/event-bearing mix and event weights are benchmark design choices, not claims about plant failure prevalence. The suite declares CC BY 4.0 for generated outputs. The prior 3,000-run purely random sizing draw realized 44 test air leaks; the new coverage policy needs a fresh generation and class-balance review. The suite is not yet a public v0.5 release. Challenge suite `suites/challenge-v0.2.yaml` includes the same event under an independently versioned runtime distribution. Challenge generation draws a hidden runtime seed and concrete ranged parameters in an evaluator-controlled process, does not persist the resolved scenario/seed, and discards the temporary case after scoring.

For event-free training data, use `suites/normal-operation-v0.1.yaml`. For normal-but-demanding false-positive stress, use `suites/false-positive-stress-v0.1.yaml`, which adds cold/warm starts, rapid recipe/load changes, high-load operation, maintenance, shutdown/restart, broad ambient ranges, and temporary sampling jitter. Both vary per-asset load setpoint, sensor noise and thermal response; every sampled process parameter is resolved into `scenario.yaml` and included in its scenario hash for replay and provenance. These ranges provide synthetic diversity and are not industrial population estimates. For the separate runtime challenge distribution, use `ot-lab challenge --suite suites/training-v0.3.yaml --challenge-suite suites/challenge-v0.2.yaml --image IMAGE --cases 100 --output RESULTS`; each case uses an independent hidden seed, and challenge outputs retain only pooled metrics, not ground truth or per-case details.

The public 1,000-run release is available from the [OT Irregularity Dataset v0.2.0 release](https://github.com/Mysthrala-Kurogane-Defense-Labs/ot-irregularity-lab/releases/tag/dataset-v0.2.0).

Create separate publishable artifacts from a completed dataset with `uv run ot-lab dataset package --dataset datasets/ot-irregularity-training-v0.4 --dataset-version 0.4.0 --data-license CC-BY-4.0 --license-file DATASET_LICENSE.txt --output releases/ot-irregularity-training-v0.4.0`. The explicit license identifier must match the suite when one is declared; suites without one require a deliberate publisher choice. For every selected partition, the command creates a telemetry ZIP (`train.zip`, `validation.zip`, `test.zip`) and a separate labels ZIP (`train-labels.zip`, etc.). The telemetry archive contains its Parquet partition, the supplied license notice, and a seed-free `release_manifest.json`; it has no ground truth. The labels archive contains independently stored per-run ground truth plus allowlisted evaluation metadata, with no seeds, source scenarios or generation metadata. Distribute the telemetry and labels archives to separate audiences when labels must remain hidden for benchmarking. The output directory release manifest records both archives' hashes and sizes, along with counts and class/event/asset distributions. Outputs are deterministic for the same dataset, version, license bytes and selected partition order. The release manifest links to the original `dataset_manifest.json` by SHA-256 without copying its per-run seeds. Challenge cases are ephemeral and cannot appear as batch partitions.

OT Irregularity Dataset v0.3.0 is generated from the same versioned v0.2 suite with simulator v0.3.0 and an independent master seed. It is a new artifact; it does not replace v0.2. See the [public release](https://github.com/Mysthrala-Kurogane-Defense-Labs/ot-irregularity-lab/releases/tag/dataset-v0.3.0), its [generation record](docs/workflows/synthetic-dataset-generation/runs/2026-10-03-training-v0.3-1000.md), and archive hash there.
