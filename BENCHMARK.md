# Model-agnostic benchmark protocol

Submission contract: a process receives only `input.parquet` and writes `output.jsonl` records with `asset_id`, `window_start`, `window_end`, and `irregularity_score` in `[0,1]`. Optional `classification` and `evidence` are descriptive. The platform imports no detector implementation.

`ot-lab benchmark --run runs/cnc-0042 --predictions results/model-a.jsonl --output results/model-a` evaluates event intervals and the expected asset sampling grid. A prediction counts for an event when its alert coverage reaches the configured overlap threshold (default 10%); the score threshold defaults to 0.5. It writes event precision/recall/F1, timestamp-level precision/recall/F1 and average precision (`window_pr_auc`), event detection rate, false-positive alert-window count, non-event alert duration, false alarms per asset-hour/day, first-detection latency, and event coverage. The generic `precision`/`recall`/`f1` fields alias event metrics. Timestamp metrics use `started_at`, `duration_s`, `sampling_interval_ms`, and `asset_ids` from run metadata, so telemetry gaps remain expected negative samples. The event precision definition counts a detected event as a true positive and an alert interval with less than the configured overlap as a false positive; `false_positive_windows` counts such alert intervals. Exposure is duration times the number of assets, including asset communication loss.

Use `ot-lab compare --run runs/cnc-0042 --predictions results/model-a.jsonl results/model-b.jsonl --output results/comparison` to score several prediction files against the same run and create `comparison.json` plus per-model reports.

Event precision uses detected events as true positives and alert windows below the event-overlap threshold as false positives. Event recall is the proportion of events detected. Timestamp/window precision and recall use the expected cadence grid; these are different measures from event precision/recall. `window_pr_auc` is average precision on that grid, not trapezoidal area. Interpret v0.1 scores as simulator benchmark results, not field-performance guarantees.

`ot-lab run-container --run RUN_DIR --image IMAGE --output predictions.jsonl` uses Docker with no network, read-only root, dropped capabilities, no-new-privileges, non-root uid, resource limits, minimal environment, and only telemetry plus an output directory mounted. Ground truth is not mounted. The baseline profile is verified locally with a Docker smoke image; daemon/host compromise, kernel escape, and adversarial images are outside its guarantee. `ot-lab challenge --suite SUITE --image IMAGE --output RESULTS` generates a fresh seed in memory, resolves declared numeric ranges, runs the container, scores its output, then removes the temporary case. Only `metrics.json` and `report.html` are retained. This local execution check does not claim adversarial container security certification.
